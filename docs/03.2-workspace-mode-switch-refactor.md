# ノートエディタ背景化リファクタリング計画 (Rev.2: Milkdownベース)

## この改訂について

- Rev.1（EasyMDEベース、`notes-background-editor-refactor.md`）からの主な変更点: エディタライブラリを EasyMDE（CodeMirror5）から **Milkdown**（ProseMirrorベースのWYSIWYGライブエディタ）に置き換える。
- Milkdownは edit/view の明示的なモード切り替えを持たない「常時ライブレンダリング」型のエディタである。そのため NotesEditor 内部で「edit ⇄ view」のモード管理をする必要がなくなり、アプリ全体としては **「キャンバスモード」「ノート(エディタ)モード」の2状態だけ** で完結する。Rev.1 の Phase 4（内部modeシグナルと`activeMode`の統合）が構造的に不要になる、というのがこの改訂の主眼。
- 一方でエディタライブラリの入れ替え自体が新しいリスクを持ち込むため、レイヤー切り替えのリファクタとは切り離した独立フェーズとして扱う。

## Milkdownを選ぶことによる設計上のシンプル化

- 現行(EasyMDE)は「テキストエリア(Markdown生テキスト編集) + `previewRender()` によるHTML変換表示」の2レンダリングパイプラインを持ち、Rev.1計画ではこれを`activeMode`に同期させる必要があった(Phase4がその対応)。
- Milkdownはドキュメントを常に1つのProseMirror State/DOMとしてレンダリングし、`readonly`（editableフラグ）で「入力を受け付けるかどうか」を切り替えるだけで済む。生テキスト⇄HTMLプレビューの変換は発生しない。
- そのため「背面=readonly Milkdown」「前面=editable Milkdown」という、**同一DOMツリーに対するフラグ切り替えだけ**で背面/前面を実現でき、Rev.1で懸念していた「previewHtmlのメモ化」「手動Edit/Viewトグルボタンの扱い」がそもそも発生しない。

## 新しいリスク（要注意点）

1. **Markdownラウンドトリップの互換性**: 既存のノートはEasyMDEで書かれたMarkdown生テキストとしてDBに保存されている。Milkdownはこれをパースし独自のシリアライザで書き戻すため、改行スタイルやリストマーカーなど、保存し直すたびに元のテキストと微妙な差分が出る可能性がある。既存ノートを開いて即座に保存し直すテストが必須。
2. **公式のSolid.js向けバインディングが存在しない**: MilkdownはReact/Vue向けの公式パッケージはあるが、Solid向けは無い。ただし現行のNotesEditor.jsxも元々EasyMDEを「Solidの外側にあるvanillaライブラリ」として`ref`経由でマウントするブリッジパターン（`registerEditorAPI`）を既に採用しているため、構造変更は小さくて済む。
3. **バンドルサイズ**: Milkdown(ProseMirrorベース)はCodeMirror5+EasyMDEより依存が重くなる可能性がある。`@milkdown/crepe`のパッケージサイズを事前に確認しておく。
4. **readonly切り替え時のフォーカス/カーソル**: ProseMirrorはreadonly化した際にフォーカスが失われる、あるいは警告が出るケースがあるため、`activeMode`が素早く往復した場合の挙動を確認する。

これらのリスクがあるため、「ライブラリ入れ替え」と「背面/前面レイヤー化」を別フェーズに分離し、先にライブラリ入れ替えだけを既存UI（スライドパネル）の上で検証してから、レイヤー化に進む。

## Phase 0 — 現状確認（コード変更なし）

- Rev.1と同じ。`grep -rn 'setActiveMode' frontend/src` で呼び出し箇所がゼロであることを確認する。

## Phase 1 — `setActiveMode` の配線

エディタライブラリに依存しない部分なので、Phase 3（Milkdown換装）と並行/どちらを先にやってもよい。

- `store.js` に次のヘルパーを追加する。
  ```js
  // Toggles between the canvas and the notes editor as the active
  // workspace mode. See docs/notes-background-editor-refactor-milkdown.md.
  export function toggleNotesMode() {
    setActiveMode((m) => (m === "notes" ? "canvas" : "notes"));
  }
  ```
- `command/command.js` の `Notes` コマンドの `execute()` で、既存の `notes.toggle()` に加えて `toggleNotesMode()` も呼ぶ（この時点ではまだ統合しない）。
- `ui/notes.js` の `close()` にも `setActiveMode("canvas")` を足す。
- 見た目は変わらない。旧doc（`workspace-mode-switch-refactor.md`）Phase 7 のチェックリストをここで初めて実地検証できる。

リスク: 低。

## Phase 2 — `Workspace.jsx` 導入・`NotesEditor` 独立化

- `Workspace.jsx` を新設し、`MindMapCanvas` と `NotesEditor` を子として持たせる。
- `NotesEditor` を `MindMapCanvas.jsx` の JSX から取り除き、`Workspace.jsx` 側に移す。
- `main.jsx` のルート定義（`/`, `/maps/:uuid`）で `MindMapCanvas` の代わりに `Workspace` をレンダリングする。
- この時点ではまだCSSレイヤー切り替えは入れない。並べるだけにして見た目が変わらないことを確認する。

確認事項: Catalogへ遷移して戻ってきたときに `NotesEditor` が正しく再初期化されるか。

リスク: 低〜中。

## Phase 3 — EasyMDE → Milkdown 換装（レイヤー化とは独立して実施）

- `frontend/package.json` から `easymde` を外し、`@milkdown/crepe`（+ 依存パッケージ）を追加する。
- `NotesEditor.jsx` の実装を書き換える。骨格は維持する（`registerEditorAPI` ブリッジパターンは踏襲）。
  ```jsx
  // NotesEditor.jsx — Milkdown Crepe replaces EasyMDE. Crepe owns its
  // own toolbar/slash-menu, so the custom Bold/Italic/... buttons in
  // #notes-editor-bar are no longer needed.
  onMount(async () => {
    crepe = new Crepe({ root: editorRootEl, defaultValue: "" });
    await crepe.create();
    crepe.on((listener) => {
      listener.markdownUpdated((_, markdown) => {
        setContent(markdown);
        notesModule.onEditorChange(markdown);
      });
    });
    notesModule.registerEditorAPI({
      setContent(text) {
        crepe.setMarkdown(text || "");
      },
    });
  });
  ```
  (実際のAPI名はMilkdown/Crepeのバージョンに合わせて要確認。上記は設計意図を示す疑似コード。)
- Crepeは独自のツールバー・スラッシュコマンドを持つため、`#notes-editor-bar` の手動Bold/Italic/…ボタン群は削除できる（Closeボタンはアプリ固有の操作なので残す）。
- **この時点ではまだ `#notes` パネルの `hidden` 属性による表示制御は変更しない。** 見た目は「スライドインするパネルの中身がMilkdownになった」だけの状態にとどめ、ライブラリ入れ替え自体の検証に集中する。
- 確認事項:
  - 既存ノート(EasyMDEで書かれたMarkdown)を開いて正しく表示されるか。
  - 編集→保存→再読み込みで内容が壊れないか（Markdownラウンドトリップ確認）。
  - `item.notes` のストレージ形式(プレーンなMarkdown文字列)は変更不要であることの確認。

リスク: 中〜高（新規ライブラリの検証が中心）。ここを独立フェーズにすることで、後続のレイヤー化フェーズと問題を切り分けられる。

## Phase 4 — 背面/前面レイヤー導入（Rev.1のPhase3+4を統合・簡略化）

- `Workspace.jsx` 内で `MindMapCanvas` と `NotesEditor` をそれぞれ `fixed inset-0` のラッパーで包み、`activeMode()` に応じて `z-index`/`pointer-events` を切り替える（`display:none` は使わない）。
  ```jsx
  // Workspace.jsx — z-index/pointer-events only, never display:none.
  <div class="fixed inset-0" style={{ "z-index": activeMode() === "canvas" ? 1 : 0 }}>
    <MindMapCanvas />
  </div>
  <div
    class="fixed inset-0"
    classList={{ "pointer-events-none": activeMode() !== "notes" }}
    style={{ "z-index": activeMode() === "notes" ? 1 : 0 }}
  >
    <NotesEditor />
  </div>
  ```
- `NotesEditor` 側の `#notes` の `hidden` 属性を外し、常にレンダリングされた状態にする。
- Milkdownのreadonly状態を `activeMode` から直接導出する。
  ```js
  // NotesEditor.jsx — no separate "mode" signal needed: Milkdown has no
  // edit/view distinction of its own, so canvas-mode simply means readonly.
  createEffect(() => {
    crepe?.setReadonly(activeMode() !== "notes");
  });
  ```
- Rev.1のPhase4で必要だった「previewHtmlのメモ化」「手動トグルボタンの扱い」は、Milkdownには元からedit/viewの区別がないため **発生しない**。
- `ui/notes.js` の `toggle()`/`close()` を `setActiveMode` 呼び出しだけに一本化する。

リスク: 中。readonly切り替え時のフォーカス/カーソル挙動を要確認（上記リスク4）。

## Phase 5 — 旧 `#note-preview` ウォーターマークの廃止・CSS再設計

- `ui/notes.js` の `init()`/`dispose()` から `#note-preview` の生成・削除コードと `updatePreview()` を削除する。
- `my-mind.css` の `#note-preview`/`#note-preview-inner` 関連スタイルを削除する。
- 背面（readonly）時の見た目を、Milkdownのルート要素に対するCSSクラス（例: `.readonly`）で表現する。旧`#note-preview-inner`のトーン（`--color-preview-ink`、セリフ体、`pointer-events: none`）を踏襲する。

リスク: 低。

## Phase 6 — Escapeの整合性確認

- `keyboard.js` は先頭で `if (!isCanvasActive()) return;` するため、Notesが前面にある間Escapeがここに届かない。`NotesEditor.jsx` 自身に `keydown` リスナーを追加し、Escapeで `setActiveMode("canvas")` を呼ぶ。ProseMirrorはメニュー展開中などでEscapeを自前で消費することがあるため、Rev.1（EasyMDE前提）より要確認度は高い。

リスク: 中。

## Phase 7 — 回帰チェックリスト

Rev.1のチェックリストに加えて:

- 既存ノート(EasyMDE時代に保存されたMarkdown)がMilkdownで壊れずに開ける。
- 編集→保存→キャンバスへ戻る→再度開く、のラウンドトリップで内容が変化しない。
- readonly⇄editableの高速な往復操作でMilkdownがクラッシュ/フリーズしない。
- ノート編集中はキャンバスのショートカット・マウス操作・ドラッグ&ドロップが一切効かない（Phase 1のガードが効いているか）。
- モバイル幅（ボトムシート表示）でも背面/前面切り替えが破綻しない。
