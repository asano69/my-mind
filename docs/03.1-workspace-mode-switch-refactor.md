# ノートエディタ背景化リファクタリング計画

## 背景・関連ドキュメント

- `docs/workspace-mode-switch-refactor.md` の Phase 1〜4（`activeMode` シグナル・`scope.js`・keyboard/mouse/clipboard/ui.js のガード）はすでに実装済み。
- ただし、その土台の上に乗るはずの **Phase 6（`Workspace.jsx` の実装）が未着手** で、`store.js` の `setActiveMode` を呼んでいる箇所が現状どこにも存在しない。つまり `activeMode` は常に `"canvas"` に固定されており、Phase 1〜4 で用意したガードは一度も実際に発火していない。
- CLAUDE.md の Work in progress は、この Workspace.jsx 実装に加えて、さらに踏み込んだゴールを要求している:
  - 現行の `#note-preview`（生HTMLのウォーターマーク、`ui/notes.js` が独自管理）を廃止する。
  - 代わりに `NotesEditor.jsx` が既に持っている EasyMDE の View モード自体を、マップの背景として常時表示する。
  - `data-command="notes"` 実行時は、背景の View モードを Edit モードに切り替えつつ、`MindMapCanvas` の手前に押し出す。

この計画は「未着手だった Workspace.jsx 導入」と「View/Edit 統合」を一本の道筋として、段階的に実装できるよう分割したものです。

## 設計方針

- **display:none は使わない。** CodeMirror のレイアウト再計算を避けるため、前面/背面の切り替えは常に `z-index` + `pointer-events` + （必要なら）`opacity` で行う（CLAUDE.md 自身の指示どおり）。
- **状態は一本化する。** 「ノートパネルが開いているか」と「activeMode」を別々の状態として二重管理しない。最終的には `NotesEditor` 自身の edit/view モードを `activeMode` から導出する一つのシグナルにする。
- **小さく刻む。** 1フェーズ＝1つの検証可能な変更にとどめ、各フェーズの終わりで見た目や挙動が壊れていないことを確認してから次に進む（`docs/mindmap-state-refactor.md` と同じ運用）。
- コード中のコメントは既存のものも新規のものも英語で統一する。

## Phase 1 — `setActiveMode` の配線（Workspace.jsx なしでできる最小変更）

まず「ノートが前面にある間はキャンバス側のショートカット・マウス操作が効かない」という、旧docのPhase 2/3で用意済みのガードを初めて実際に機能させる。

- `store.js` に `leftPanelHidden`/`rightPanelHidden` と同じ形で、次のヘルパーを追加する。
  ```js
  // Toggles between the canvas and the notes editor as the active
  // workspace mode. See docs/notes-background-editor-refactor.md.
  export function toggleNotesMode() {
    setActiveMode((m) => (m === "notes" ? "canvas" : "notes"));
  }
  ```
- `command/command.js` の `Notes` コマンドの `execute()` で、既存の `notes.toggle()` に加えて `toggleNotesMode()` も呼ぶ（この時点ではまだ2つの状態を並行して動かすだけで、統合はしない）。
- `ui/notes.js` の `close()`（Escape や他パネルからの明示クローズ用）にも `setActiveMode("canvas")` を足す。
- 見た目は一切変わらない。旧doc Phase 7 のチェックリストを、ここで初めて実地検証できるようになる。

リスク: 低。見た目に影響しない状態追加のみ。

## Phase 2 — `Workspace.jsx` の導入、`NotesEditor` の独立化

次フェーズで「常時マウント・常時レンダリング」にするための下地を作る。

- `Workspace.jsx` を新設し、`MindMapCanvas` と `NotesEditor` を子として持たせる。
- `NotesEditor` を `MindMapCanvas.jsx` の JSX から取り除き、`Workspace.jsx` 側に移す。
- `main.jsx` のルート定義（`/`, `/maps/:uuid`）で `MindMapCanvas` の代わりに `Workspace` をレンダリングする。
- この時点ではまだCSSレイヤー切り替えは入れない。単に子として並べるだけにして、見た目が変わらないことを確認する（`NotesEditor` は引き続き `#notes` の `hidden` 属性で表示制御されたまま）。

確認事項（要検証）:
- `MindMapCanvas` は `onMount`/`onCleanup` で `engine.mount()`/`unmount()` を呼んでいる。`NotesEditor` がその外側（`Workspace` 直下）に出ても、Catalog への遷移時に `Workspace` ごとアンマウントされるなら実害はないはず。念のため、Catalogへ行って戻ってきたときに `NotesEditor` が正しく再初期化されるか確認する。

リスク: 低〜中。

## Phase 3 — 背面/前面レイヤーの導入（CSSのみ、まだ見た目は仮）

- `Workspace.jsx` 内で `MindMapCanvas` と `NotesEditor` をそれぞれ `fixed inset-0` の薄いラッパーで包み、`activeMode()` に応じて `z-index` と `pointer-events` だけを切り替える。
  ```jsx
  // Workspace.jsx — z-index/pointer-events only, never display:none
  // (CodeMirror inside NotesEditor would redo its layout math otherwise).
  <div class="fixed inset-0" style={{ "z-index": activeMode() === "canvas" ? 1 : 0 }}>
    <MindMapCanvas />
  </div>
  <div
    class="fixed inset-0"
    classList={{ "pointer-events-none": activeMode() !== "notes" }}
    style={{ "z-index": activeMode() === "notes" ? 1 : 0 }}
  >
    <NotesEditor />
  </div>
  ```
- `NotesEditor` 側の `#notes` の `hidden` 属性を外し、常にレンダリングされた状態にする。
- 見た目のデザインはまだ本対応しない（Phase 5でやる）。ここでは「背面にいる間、崩れた見た目のまま透けて見えても許容する」段階でよい。

リスク: 中。`hidden` 属性除去後、CodeMirror が正しい寸法で初期化されるか要確認（これが CLAUDE.md が `display:none` を避けろと明記している理由そのもの）。

## Phase 4 — `NotesEditor` の edit/view モードを `activeMode` に統合

ここが本命の変更。

- `NotesEditor.jsx` 内の独立した `mode` シグナルを廃止し、`activeMode() === "notes" ? "edit" : "view"` から導出する `createMemo` に置き換える。
- `previewHtml` は現状 `toggleMode()` 内でのみ計算されている。これを `content()` が変わるたびに再計算される `createMemo` に変更し、背面にいる間も常に最新のプレビューが表示されるようにする。
- ツールバーの手動 Edit/View トグルボタンは撤去する（デフォルト案）。理由: `activeMode` を切り替えれば自動的に view/edit が連動するため、パネル内に独立したトグルを残すと状態が二重管理に戻ってしまう。前面のまま一時的にプレビューだけ見たい、という要望が出た場合は別途検討。
- `ui/notes.js` の `toggle()`/`close()` を `setActiveMode` の呼び出しだけに一本化し、`node.hidden = ...` の操作を削除する。

未決事項（要判断、デフォルト案を併記）:
1. 手動Edit/Viewトグルボタンを完全撤去してよいか → デフォルト: 撤去。
2. 前面（Edit）時のレイアウトは現行の50%幅パネルのままでよいか、全画面にするか → デフォルト: 現状維持（変更点を最小化）。

リスク: 中〜高。既存の自動テストにNotesEditor向けのものは見当たらないため、手動での回帰確認が必須。

## Phase 5 — 旧 `#note-preview` ウォーターマークの廃止・CSS再設計

- `ui/notes.js` の `init()`/`dispose()` から `#note-preview` の生成・削除コードと `updatePreview()` を削除する。
- `my-mind.css` の `#note-preview`/`#note-preview-inner` 関連スタイルを削除する。
- 背面（View・canvas手前）用のスタイルを新設する。旧 `#note-preview-inner` の見た目（`--color-preview-ink`、セリフ体、`pointer-events: none`）を踏襲しつつ、`NotesEditor.css` の View ペイン（`#notes-editor-view-pane`）に適用する形にする。

リスク: 低（装飾レベルの変更のみ）。

## Phase 6 — キーボード周りの整合性確認（Escape）

- `keyboard.js` は先頭で `if (!isCanvasActive()) return;` するため、Notes が前面にある間 Escape がここに届かない。`NotesEditor.jsx` 自身に `keydown` リスナーを追加し、`Escape` で `setActiveMode("canvas")` を呼ぶようにする。CodeMirror / EasyMDE が Escape を自前で消費しないか要確認。
- `command/edit.js` の `Cancel` コマンドが呼んでいた `notes.close()` は Phase 4 の変更で自然に `setActiveMode("canvas")` へ置き換わっているはずなので、`help.close()`/`io.hide()` との同時実行順序に問題がないか再確認する。

リスク: 中。
